## Quick Start

This repository runs locally with synthetic transactions generated by the rule-based stage, so a fresh clone does not need the Kaggle dataset to execute the main pipeline.

### Setup

1. Create and activate a Python 3.12 virtual environment.
2. Install dependencies:

```bash
pip install -r requirements.txt
```

### Run

From the repository root, run the final pipeline entry point:

```bash
python src/final_flagging.py
```

Or run the main entrypoint directly from the repository root:

```bash
python src/main.py
```

This runs the full chain end to end:

1. Synthetic transaction generation in `src/intial_rule_filltering.py`.
2. Rule-based filtering in `src/supervised.py`.
3. Isolation Forest scoring in `src/random_forest_model_flagging.py`.
4. Final flagged report output in `src/final_flagging.py`.

### Data Source

The Kaggle `SAML-D.csv` dataset is optional for this code path. If you want to use it for experiments or notebooks, place it in `data/` at the repository root.
When it comes to detecting money laundering, a single machine learning model just doesn't cut it. Financial data is messy, heavily imbalanced, and adversarial—criminals are constantly tweaking their methods to stay under the radar. To tackle this, I built a hybrid, dual-model architecture rather than relying on one algorithm to do it all
Why a Hybrid Approach? (Unsupervised + Supervised)
If you only use a supervised model, you leave a massive blind spot for "zero-day" laundering tactics. If a bad actor invents a new structuring technique that isn't in your historical training data, a supervised model will likely just wave it through as normal behavior
#The Safety Net (Unsupervised): The first layer acts as an independent check. It evaluates the raw behavioral metrics to flag mathematical abnormalities, completely ignoring human-defined labels.
#The Filter (Supervised): The second layer takes those unsupervised anomaly scores, combines them with known rule-based flags, and makes the final call. This is crucial for slashing the massive volume of false positives that usually drown traditional rule-based banking systems.
The Unsupervised Layer: Isolation ForestI chose Isolation Forest over distance-based or density-based algorithms (like KNN or DBSCAN) for a few practical reasons:Built for Scale: It has a linear time complexity of $O(n \log n)$ and uses data sub-sampling. This means it can chew through massive datasets (like millions of transaction logs) quickly and with a low memory footprint.Handles High Dimensionality: It maintains its performance even when processing dozens of complex engineered features, like rolling 24-hour velocity or balance ratios, avoiding the curse of dimensionality.The Underlying Logic: Instead of trying to define what "normal" banking looks like (which is incredibly diverse and noisy), Isolation Forest explicitly tries to isolate the anomalies. This aligns perfectly with financial fraud, where malicious transactions are inherently "few and different."
The Supervised Layer: XGBoost
For the final decider model, XGBoost was the clear choice, particularly because of its performance on highly imbalanced classification tasks.
Tackling Class Imbalance: Fraud datasets are notoriously skewed. By using tunable parameters like scale_pos_weight and integrating SMOTE into the training pipeline, the model is forced to heavily penalize false negatives rather than simply memorizing the majority class.
Connecting the Dots: As a tree-based ensemble, it is fantastic at learning complex "OR" logic. It can learn to flag an account if it triggers a known smurfing rule, or if its unsupervised anomaly score is exceptionally high despite passing the basic rules.
Regulatory Explainability: In heavily regulated industries, black-box AI is often a non-starter. XGBoost provides clear feature importance metrics, ensuring that every alert generated by this pipeline can be backed by a human-readable reason for compliance auditing.
